# LedgerLens Product Reset Working Agreement

1. The branch stays buildable after executable changes.
2. Prototype compatibility is not preserved without an explicit data-retention contract.
3. Financial correctness outranks UI convenience.
4. Privacy and distribution constraints are product requirements, not release paperwork.
5. Parser output never silently becomes user-confirmed truth.
6. User corrections survive parser upgrades.
7. Rules are declarative, deterministic, previewable, and reversible.
8. Old code is removed only after replacement behavior is exercised.
9. Every meaningful work unit updates the control and critique logs.
10. Assistant self-review never substitutes for independent adversarial review.
11. Blocker/high findings remain visible until resolved or explicitly accepted with rationale.
12. The user should experience goals and results, not internal pipeline operations.
